# Changelog

Release notes for Forge UI. Each package also has its own changelog, generated by Changesets when it is released.

## 0.1.0

The first release. Ten components, each in its own package, plus `@forge-ui/core` for tokens and shared pieces.

### Components

- **Data table**: sorting, global and per-column filtering, pagination, server-side mode, column visibility, resizing and pinning, row selection and expansion, virtualized rendering, CSV export with spreadsheet-formula protection, and grid keyboard navigation.
- **Command palette**: fuzzy search, groups, nested and lazily loaded commands, async results, recent history, and a configurable global shortcut.
- **File uploader**: drag and drop, validation, image previews, progress, retry with backoff, cancel, pause and resume, a concurrency-limited queue, and a small adapter interface with an XHR adapter included.
- **Form system**: any Standard Schema validator, async validation, conditional fields, field arrays, multi-step forms, and accessible error handling, on top of React Hook Form.
- **Combobox** and **multi-select**: async options, grouping, disabled options, custom rendering, and windowed lists for very large option sets.
- **Date-range picker**: single dates and ranges, min and max dates, disabled dates, range length limits, presets, and locale-aware formatting through Intl.
- **Notifications**: `notify` with variants, `notify.promise`, undo, progress, queueing, and screen reader announcements.
- **Activity timeline**: grouped events, avatars, icons, metadata, relative or absolute times, and loading and empty states.
- **Kanban board**: pointer, touch, and keyboard drag and drop, a Move to… menu, work-in-progress limits, and optimistic persistence with rollback.

### Known limitations

- The data table's expandable rows cannot be combined with virtualization.
- The data table supports flat headers only. Grouped column headers are not supported yet.
- The date picker does not accept typed input. Dates are chosen from the calendar.
- Pointer drag and drop in the kanban board is covered by end-to-end tests rather than unit tests, because jsdom has no layout.
